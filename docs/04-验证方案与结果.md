# 校园活动管理系统 V1.0 — 验证方案与结果

## 验证方式

验证不局限于"程序能否启动"，而是使用 Flask 测试客户端（`app.test_client()`）驱动完整的 HTTP 请求流程，
在真实的路由、服务、数据库链路上执行注册登录、发布活动、浏览、报名、取消、管理等业务过程，
并检查关键业务规则与异常情况是否被正确拦截。

- 验证脚本：`tests/verify_v1.py`
- 运行方式：`python tests/verify_v1.py`
- 可复现性：脚本每次运行会删除并重建 `data.db`，因此结果不依赖历史数据，可重复执行

## 7.2 问题修复与回归验证

本次验证首次执行即全部通过，未发现需要修复的功能缺陷，故无问题修复记录。

验证过程中额外确认了三个容易出错的实现细节，均符合设计预期：

1. **取消后重新报名**：由于 `UNIQUE(user_id, activity_id)` 约束存在，取消时若物理删除记录会丢失历史，
   若不删除则重新报名会撞唯一约束。实现采用"存在则更新状态"的策略，两种需求同时满足（对应设计决策 2、3）。
2. **时间字段格式统一**：前端 `datetime-local` 产生 `YYYY-MM-DDTHH:MM`，与数据库中 `YYYY-MM-DD HH:MM` 不同。
   服务层统一归一化，避免字符串比较出现偏差。
3. **越权防护位置**：教师操作活动的归属校验放在服务层而非仅依赖页面隐藏按钮，
   验证中用另一教师账号直接构造请求，确认被服务层拦截。
